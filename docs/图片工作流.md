# 图片工作流：Cloudflare R2

图片**不放进 Git 仓库、不进 Astro 构建**，而是上传到 Cloudflare R2（对象存储），
再由站点自己的 `/img/` 路径发出去。

好处：

- 仓库一直很小，`git clone` 和构建都快，构建内存低。
- R2 **出站流量免费**（这是它比 S3 香的地方），配合 Cloudflare CDN 全球缓存。
- 图想加多少加多少，跟代码解耦。

代价：Astro 不会自动优化它管不到的图。所以**上传前自己压一遍**（见第 4 节），
否则原图多大读者就下多大。

## 它是怎么接上的

```
读者请求 /img/2026/foo.webp
        │
        ├─ 路径匹配 /img/*  ──> worker/index.js ──> R2 桶 image
        │
        └─ 其他所有路径     ──> 直接由资源层发出（不进 Worker，没有冷启动）
```

分流规则写在 `wrangler.jsonc` 的 `run_worker_first: ["/img/*"]`。
这一行是「这个站基本还是纯静态」这句话成立的原因。

**为什么不用 R2 自带的公开地址**（`https://pub-xxxx.r2.dev/...`）：

1. 那个地址会被写死在每篇文章的 markdown 里。以后绑了自己的域名、或者换了桶，
   每一篇引用过图的文章都得改。走 `/img/` 写的是相对路径，域名换成什么都不用动正文。
2. Cloudflare 自己说 r2.dev 有速率限制、不建议用于正式环境。

给桶单独绑一个子域（`img.clarkebelt.org`）现在也做得到了。但没必要换 ——
`/img/` 这条路已经在跑，换过去要重写每篇文章里的图片地址，白折腾。
真要用的场景是想让图片走独立缓存策略，目前没这个需求。

## 1. 一次性设置

### 建桶

**顺序很重要：桶必须先存在，再推 `wrangler.jsonc`。** 配置里的 `r2_buckets`
指向一个不存在的桶时，`wrangler deploy` 会直接失败——线上已有的版本还在跑，
但这次构建不会上线。

命令行（先登录，会开浏览器）：

```bash
npx wrangler login
npx wrangler r2 bucket create image
```

或者在面板里：Dashboard → R2 → *Create bucket*，名字填 `image`。

> 桶名要和 `wrangler.jsonc` 里的 `bucket_name` 一致。想换名字就两边一起换。
>
> 账号第一次启用 R2 时，面板**可能**会要求你填付款方式。免费额度
> （10 GB 存储、每月 100 万次写、1000 万次读）仍然是免费的。

### 不需要做的事

- **不用开 Public Development URL。** 图片是通过你自己的 Worker 发的，
  桶保持私有就行——这样也没人能绕过你的域名直连桶。
- **不用建 API Token**，除非你要用 rclone（见下一节）。
  `wrangler` 用你登录的身份，不需要额外 token。

## 2. 上传

### 少量：wrangler

```bash
npx wrangler r2 object put image/2026/dyson-sphere.webp \
  --file=./dyson-sphere.webp
```

对象名（`2026/dyson-sphere.webp`）就是以后 URL 里 `/img/` 后面那一截。
按年份分目录只是个建议，R2 里没有真正的目录，斜杠只是名字的一部分。

### 批量：rclone

一整个文件夹同步上去用 `rclone` 最省事。它走 S3 协议，所以要单独建 token：
R2 → *Manage R2 API Tokens* → *Create API Token*，权限 *Object Read & Write*。
记下 Access Key ID、Secret Access Key，以及 S3 endpoint
`https://<账户ID>.r2.cloudflarestorage.com`。

```bash
rclone config
# 交互里选：
#   n) 新建 remote，名字填 r2
#   Storage 选 s3
#   provider 选 Cloudflare
#   access_key_id / secret_access_key 填上面两个 key
#   region 填 auto
#   endpoint 填 https://<账户ID>.r2.cloudflarestorage.com
```

之后：

```bash
rclone copy ./图片准备好 r2:image/2026/ -P
```

## 2.5 后台直传（不用命令行）

Sveltia CMS 从 0.172 起把 Cloudflare R2 列为一等媒体库，我们钉的版本就有。
配置在 `public/admin/config.yml` 的 `media_libraries` 那一段，默认是注释状态 ——
**要先做两件只能在 Cloudflare 面板里做的事**，步骤写在那段注释里：建一个
Object Read & Write 的 R2 API Token，再给桶配 CORS。

开了之后的样子：后台里点「配图」旁边的媒体库按钮 → 拖一张图 → 它在**浏览器里**
转成 webp、压到 1600px、传进 `image` 桶 → 把
`https://clarkebelt.org/img/2026/xxx.webp` 直接写回字段。

几件值得先知道的事：

- **压缩是在浏览器里做的**，不经过任何服务器。所以第 4 节那条 sharp-cli 命令，
  走后台这条路就不用跑了。参数在 `media_libraries.default.config.transformations`。
- **弹窗里会有两个来源，选 R2 那个。** 「仓库」那个来源存进 `ogImage` 的是
  `/images/...` 相对路径，会让构建失败。
  为什么不干脆把仓库那个来源关掉 —— 见下面「一个互斥关系」。
- **输出格式只能是 webp。** 代码里的白名单就一项，填别的会被静默改成 webp。
  能被转的输入是 avif / gif / jpeg / png / webp；HEIC 之类不在列，会原样传上去
  ——不报错，但也没压。iPhone 直接导出的图要留意这一条。
- **上传时选不了目录。** 对象名 = 配置里的 `prefix` + 文件名，界面上没有
  「传到哪个文件夹」这个选项。所以年份目录写死在 `prefix: 2026/`，跨年要改配置。
- **Secret Access Key 不进配置文件。** 后台第一次打开媒体库时问你要，存在浏览器
  本地。`config.yml` 是公开可读的（`https://clarkebelt.org/admin/config.yml`），
  里面只有 Access Key ID，那个东西单独拿不到任何权限。
- **必须写 `acl: false`。** 上传代码默认会带一个 `x-amz-acl: public-read`，
  而 R2 的 S3 兼容接口没实现 ACL（官方兼容性表里这个头是 ❌）。

### 一个互斥关系（踩过）

「只让这个字段选 R2」和「上传时自动压缩」，在 Sveltia 0.172.4 里**不能同时要**。

字段上写 `media_libraries: { default: false }` 能达到前者，但会让后者连同
`slugify_filename`、`max_file_size` 一起失效。实证：那次上传进桶的是
`AtomicRocketSeal256.png` —— 既没转 webp，也没被 slugify。

原因是它读配置的那条路：

```js
EF = ({ libraryName = `default`, fieldConfig: t }) => {
  if (t?.media_libraries && e in t.media_libraries) {
    let n = t.media_libraries[e];
    return n !== !1 && i(n); // ← 字段级 false，直接 return false
  }
};
OF = ({ fieldConfig: e }) => {
  let t = EF({ fieldConfig: e }),
    { transformations, slugify_filename, max_file_size } =
      typeof t == `boolean` ? {} : (t?.config ?? {}); // ← 从 {} 里取，全丢
};
```

而且没有绕路：`OF` 永远只查 `default` 这一项（所有调用点都没传
`libraryName`），所以把 `transformations` 挪到 `cloudflare_r2` 底下、
或者塞进 `media_libraries.all`，都读不到。

**取的是压缩。** 压缩是每个读者每次都要付的成本，「选错来源」只是一次误操作。
守卫改由 `scripts/check-posts.mjs` 承担：

- `ogImage` 不是绝对地址 → **报错并中断**，附上正确写法。
  比等构建炸出一个 `[ImageNotFound]` 清楚得多。
- `ogImage` 不是 webp → **只提醒不中断**。它同时是个信号：
  出现非 webp 说明上面那段 `transformations` 又没生效了。

命令行那条路（第 2 节）没有被取代 —— 批量传几十张图还是 `rclone` 快。

## 3. 在文章里引用

普通 Markdown，**相对路径**：

```markdown
![戴森球示意图](/img/2026/dyson-sphere.webp)
```

不需要 import、不需要组件、不需要改 `astro.config.ts`。

图多的时候（画廊那种），把文章后缀改成 `.mdx`，用 HTML 排版：

```html
<figure>
  <img src="/img/2026/a.webp" alt="..." loading="lazy" />
  <figcaption>图注</figcaption>
</figure>
```

## 3.5 首页封面图

`ogImage` 这一栏是**双用途**的：既是分享卡片的图，也是首页 / 归档列表里
那张缩略图（`Card.astro` 直接复用它）。填了就有图，不填卡片就是纯文字。

后台里这一栏是 `widget: image`，点按钮就能从 R2 选或者直接拖一张上传，
**不用手打地址**。它的 `media_libraries: { default: false }` 关掉了仓库那个库，
所以选出来的只可能是绝对地址 —— 下面这条规则被配置本身兜住了。
手写 markdown 的时候还是得自己遵守：

**必须填完整绝对地址**，不能填 `/img/...`：

```yaml
ogImage: https://clarkebelt.org/img/2026/dyson-sphere.webp
```

这一条是实测过的（2026-07-25）。填站内相对路径会让**构建直接失败**：

```
[ImageNotFound] Could not find requested image `/img/2026/cover-test.webp`
```

原因是 schema 里写的是 `image().or(z.string())`，Astro 会先把它当**构建时的本地资源**
去解析，而 R2 上的东西构建时根本不存在。分享卡片的 `og:image` 按规范本来也要求
绝对地址，所以这里填绝对地址是语义上正确的，不是将就。

**代价说清**：域名被写进了每篇文章的 frontmatter。哪天换域名，正文里的
`/img/...` 一个都不用动（那是相对路径），但这一栏要批量改：

```bash
grep -rl "clarkebelt.org/img/" src/content/posts/ \
  | xargs sed -i 's|https://clarkebelt.org/img/|https://新域名/img/|g'
```

**封面图单独压一版，别用正文图的尺寸。** 缩略图在 CSS 里是
`h-44 w-full`（手机）/ `sm:h-28 sm:w-44`（桌面 176×112），走 `object-cover` 裁切。
所以 880px 宽足够，用第 4 节那条 1600px 的配方是浪费：

```bash
npx sharp-cli --input ./封面原图.jpg --output ./图片准备好 \
  resize 880 --withoutEnlargement --format webp -- --quality 80
```

尺寸不会跳版（CLS）——高宽都由 CSS 固定，不依赖图片自身尺寸。

### 封面要横构图，别用方图或竖图

`Card.astro` 用的是 `object-cover` —— **填满并裁掉多余部分**，不是缩放到装得下。
而那个框有两套尺寸，**手机那套的长宽比还不是固定的**：

| | 框 | 长宽比 | 方图会被裁掉 |
| --- | --- | --- | --- |
| 桌面（`sm:` 以上） | 176×112 | 1.57 : 1 | 上下各 18%（合计 36%） |
| 手机 @390px 宽 | 358×176 | 2.03 : 1 | 上下各 25%（合计 51%） |
| 手机 @639px 宽 | 607×176 | 3.45 : 1 | 上下各 35%（合计 71%） |

手机那两行不是笔误：CSS 写的是 `h-44 w-full`，高固定 176px、宽跟着屏幕走，
所以**长宽比在 2.0 到 3.45 之间连续变**。换句话说没有哪个画布尺寸能在手机上
「永不裁切」，只能保证**主体落在画布垂直方向正中那 58% 的带子里**
（58% = 1 ÷ 3.45 × 2，最窄的那一档看得见的就是这一条）。

这条是踩出来的：`AtomicRocketSeal256.png` 是 256×255 的圆形徽章，
装进那个框之后「ATOMIC ROCKETS」和「SEAL OF APPROVAL」两行弧形文字
上下都被切没了，看着像个残缺的圆。

**碰上非横构图的素材，先补成横幅再传** —— 补到 **880×440（2:1）**，
主体自己别超过 255px 高，正好落在那条 58% 的带子里：

```bash
npx sharp-cli --input ./方形徽章.png --output ./图片准备好 \
  resize 880 440 --fit contain --withoutEnlargement \
  --background "#0d1729" --format webp -- --quality 82
```

两个参数都是必需的，缺一个就白做：

- `--fit contain` —— 缩放到装得下并补背景色，不裁内容。
- **`--withoutEnlargement`** —— 不许放大。少了它，那张 256px 的徽章会被拉到
  440px 高去填满画布（放大 1.7 倍），糊；而它实际显示出来只有 176~360px 宽，
  放大纯粹是负收益。这和第 4 节「小图不放大」是同一条规矩。
  实测：加了这个参数，画布是 880×440，徽章保持 256×255 居中。

底色挑一个和图本身协调的（上面那个是站点的深色前景色）。

> 想改成「永不裁切」也可以：把 `Card.astro` 里那个 `object-cover` 换成
> `object-contain`。但代价是**照片类封面会出现上下留白**，而照片是更常见的情况。
> 所以默认留 `object-cover`，由上传前的构图来配合。

## 4. 上传前压缩（走命令行时才需要）

> 走第 2.5 节的后台直传的话跳过这一节 —— 转码在浏览器里已经做掉了。
> 这一节是 `wrangler` / `rclone` 那条路的必修课。

远程图 Astro 不帮你优化，务必上传前转 WebP 并限制尺寸：

```bash
npx sharp-cli --input "./原图/*.{jpg,png}" --output ./图片准备好 \
  resize 1600 --withoutEnlargement \
  --format webp -- --quality 80
```

- `resize 1600` = 最长边压到 1600px，博客正文足够。
- `--withoutEnlargement` = 小图不放大。
- WebP quality 80 一般肉眼无损，体积砍到 1/3 ~ 1/5。

## 5. 一条规矩：换内容就换文件名

Worker 给图片发的缓存头是 `public, max-age=604800`（7 天）。
所以**同一个文件名换了内容，读者最多有一周看到的还是旧图**。

不要试图靠改缓存时间绕过这件事——把时间调短就等于放弃缓存。
正确做法是换名字（`foo.webp` → `foo-v2.webp`），R2 存储便宜、出站免费，
多留一个旧文件不花什么钱。

7 天之后浏览器会带 `If-None-Match` 来问一次，没变就是一个 304，很便宜。
这部分逻辑在 `worker/index.js` 里。

## 6. 边界

- **后台能不能往 R2 上传，取决于有没有开第 2.5 节那段配置。** 没开的话它的媒体库
  只指向仓库里的 `public/images`，适合偶尔一张小图；开了就是直传 R2。
- **本地 `npm run dev` 看不到 R2 的图。** `/img/` 是 Worker 路由，
  只在部署后存在；本地那个路径是 404。要在本地验证得跑 `npx wrangler dev`，
  而它需要 workerd（安装时被 npm 的脚本拦截拦下了，用到再放行）。
- **Cloudflare Image Transformations**（按需缩放，`/cdn-cgi/image/width=800/...`）
  现在够条件用了 —— 它要一个托管在 Cloudflare 的域名，`clarkebelt.org` 就是。
  开了之后可以省掉第 4 节的手动压缩：上传原图，尺寸交给 CDN 现算。
  要去 Dashboard 的 Images → Transformations 给这个域名手动启用，
  且免费额度是按「每月唯一转换数」算的，不是无限。没启用之前照旧走第 4 节。
- **故意不给 Astro 加 `image.domains`。** 那样构建时会去下载每张远程图再处理，
  又慢又吃内存，等于把 R2 的好处抵消掉。图片优化交给「上传前压缩 + CDN 缓存」。
