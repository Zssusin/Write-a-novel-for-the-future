# 图片工作流

图片放在 **`src/content/posts/img/`**，跟文章躺在一起，剩下的 Astro 全包。

```markdown
![这张图在说什么](./img/dyson-sphere.webp)
```

没有别的步骤。不用量尺寸、不用改文件名、不用先压、不用上传。

> **2026-08-26 之前不是这样。** 那时候图在 Cloudflare R2 上，正文写
> `/img/2026/dyson-sphere-1600x900.webp` —— 文件名末尾那个 `-宽x高` 是必需的，
> 还得自己压、自己传、自己生成封面缩略图。整套换掉的原因和代价写在最后一节。

## 为什么这样就够了

关键在于 **`src/` 底下的图 Astro 当成「本地资源」**。构建时它会：

| 它做的事 | 以前谁在做 |
| --- | --- |
| 量出宽高，写进 `<img>` 的 `width`/`height`（防跳版） | 你，写在文件名里 |
| 按用途生成各档尺寸 + `srcset` | 你，跑 `make-thumbs.mjs` |
| 转码压缩 | 你，跑 `sharp-cli` |
| 文件名加内容哈希 | 你，手动改名（「换内容就换文件名」那条规矩） |
| 部署 | 你，跑 `upload-img.mjs` |

那四个脚本步骤现在一个都不需要了。放 `public/` 或者写外链都拿不到这一套 ——
**必须在 `src/` 底下，必须是相对路径。**

## 1. 从后台放图（主路径）

正文里点插图按钮、或者直接把图**粘贴**进来（选图弹窗的上传区有粘贴按钮），
选文件、确定。就这样。

后台会自动做两件事，配置在 `public/admin/config.yml`：

- **转 webp、压到最长边 1600px**（`media_libraries.default.config.transformations`）。
  图片现在进 git 仓库，这一步比以前更值钱。
- **文件名转拼音/英文**（`slugify_filename`）。中文文件名会变成一串百分号编码。

存进去的路径是 `./img/xxx.webp`，落到 `src/content/posts/img/`。

> 这靠的是 posts 集合上的 `media_folder: img` —— Sveltia 里不以 `/` 开头的
> 相对路径是**相对 collection 的 `folder`** 解析的，所以正好落在文章旁边。
>
> **只有一个上传目标。** 以前弹窗里会同时列出「仓库」和「R2」两个来源，
> 每次插图都得先想「这张该进哪个」，选错了不当场报错、过一会儿构建才炸。
> R2 那条撤掉之后没得选了，也就不会选错。

## 2. 手写 markdown

放一张图进 `src/content/posts/img/`，正文里：

```markdown
![替代文字](./img/文件名.webp "可选的图注")
```

`./` 可以省（`img/文件名.webp` 也认），写全只是为了一眼看出这是相对路径。

本地 `npm run dev` **能看到图** —— 这是搬回仓库之后才有的。以前 `/img/` 是
Worker 路由，只在部署后存在，本地永远是 404，图对不对只能等上线才知道。

## 3. 替代文字：唯一还得你写的东西

方括号里那句话是给读屏的人的，机器补不了 —— 那是判断，不是变换。

```markdown
![NERVA XE 核热火箭在夜间泛光灯下被运往内华达的试车台](./img/rho-nerva.webp)
```

写「这张图在说什么」，别写「一张图片」，更别留空让读屏器去念文件名
（`alt="File:Homura face.png"` 就是这么来的）。

`npm run check:posts` 会数出有几张欠着，**只提醒、不拦构建**。
纯装饰、说了反而添乱的图，留空是对的，忽略那条提醒就行。

## 4. 首页封面图（`ogImage`）

这一栏是**双用途**的：分享卡片的图，同时也是首页 / 归档列表里的缩略图
（`Card.astro` 直接复用）。填了就有图，不填卡片就是纯文字。

```yaml
ogImage: ./img/dyson-sphere-cover.webp
```

跟正文图一样，相对路径。后台里点按钮上传就行，不用手打。

> **这条规则 2026-08-26 反了过来。** 以前必须填 `https://clarkebelt.org/img/...`
> 这种完整绝对地址，填相对路径会让构建直接失败（`[ImageNotFound]`）。
> 现在相反：相对路径才拿得到 Astro 的处理，绝对地址只是能显示而已，
> `check:posts` 会提醒你搬进来。

Astro 从这一张图里生出两样东西：

- **列表缩略图** —— 440 宽那档，加 `srcset`。桌面首屏那张约 14.5KB。
- **分享卡片** —— 拿原图，`og:image` 里是绝对地址（Astro 自己拼的）。

所以封面**不用单独压一版**，也不用跑 `make-thumbs.mjs`（那个脚本已经没用了）。

一个附带好处：域名不再被写进每篇文章的 frontmatter。以前换域名要批量 sed
所有 `ogImage`，现在正文和 frontmatter 里一个域名都没有。

### 封面要横构图，别用方图或竖图

这条**完全没变**，是构图问题不是技术问题。

`Card.astro` 用 `object-cover` —— **填满并裁掉多余部分**，不是缩放到装得下。
而那个框有两套尺寸，**手机那套的长宽比还不是固定的**：

| | 框 | 长宽比 | 方图会被裁掉 |
| --- | --- | --- | --- |
| 桌面（`sm:` 以上） | 176×112 | 1.57 : 1 | 上下各 18%（合计 36%） |
| 手机 @390px 宽 | 358×176 | 2.03 : 1 | 上下各 25%（合计 51%） |
| 手机 @639px 宽 | 607×176 | 3.45 : 1 | 上下各 35%（合计 71%） |

手机那两行不是笔误：CSS 写的是 `h-44 w-full`，高固定 176px、宽跟着屏幕走，
所以**长宽比在 2.0 到 3.45 之间连续变**。没有哪个画布尺寸能在手机上「永不裁切」，
只能保证**主体落在画布垂直方向正中那 58% 的带子里**
（58% = 1 ÷ 3.45 × 2，最窄的那一档看得见的就是这一条）。

这条是踩出来的：`AtomicRocketSeal256.png` 是 256×255 的圆形徽章，装进那个框
之后「ATOMIC ROCKETS」和「SEAL OF APPROVAL」两行弧形文字上下都被切没了，
看着像个残缺的圆。

**碰上非横构图的素材，先补成横幅** —— 补到 **880×440（2:1）**，主体自己
别超过 255px 高，正好落在那条 58% 的带子里：

```bash
npx sharp-cli --input ./方形徽章.png --output ./准备好 \
  resize 880 440 --fit contain --withoutEnlargement \
  --background "#0d1729" --format webp -- --quality 82
```

两个参数缺一个就白做：

- `--fit contain` —— 缩放到装得下并补背景色，不裁内容。
- **`--withoutEnlargement`** —— 不许放大。少了它，那张 256px 的徽章会被拉到
  440px 高去填满画布（放大 1.7 倍），糊；而它实际显示出来只有 176~360px 宽，
  放大纯粹是负收益。实测：加了这个参数，画布是 880×440，徽章保持 256×255 居中。

底色挑一个和图本身协调的（上面那个是站点的深色前景色）。

> 想改成「永不裁切」也可以：把 `Card.astro` 里的 `object-cover` 换成
> `object-contain`。但代价是**照片类封面会出现上下留白**，而照片是更常见的情况。
> 所以默认留 `object-cover`，由构图来配合。

## 5. 手写 `<img>` 的话，什么都得自己写

Astro 和 `imageAttrs.ts` 都**只处理 markdown 的 `![](...)` 写法**。
手写的 HTML 它们看不到 —— `.md` 里的原始 HTML 是整块 raw 文本
（管道里没有 `rehype-raw`），`.mdx` 里的 `<img>` 是 JSX 节点。这是实测过的。

图多的时候（画廊那种）想用 `.mdx` 排版，尺寸和 `loading` 得自己写全：

```html
<figure>
  <img src="./img/a.webp" width="1600" height="900" loading="lazy"
       decoding="async" alt="..." />
  <figcaption>图注</figcaption>
</figure>
```

漏写 `width` 的手写标签，`npm run check:posts` 会单独点名。

## 6. 边界

- **图片进 git。** 这是这套办法的全部代价。迁过来时 19 张一共 1.2 MB，
  这个量级不值得为它维护第二条路。真涨到几百兆，回来看最后一节。
- **图片不在文章的 CC 授权范围内。** `src/content/posts/img/**` 被
  [LICENSE-content](../LICENSE-content) 明确排除出去了 —— 里面混着公有领域的
  航天照片、按合理使用收录的书影和动画截图、本站自制的图表，权利状态完全不同。
  文件躺在这个公开仓库里，不代表本仓库有权把它许可给别人。**加图时想一下这条。**
- **`image.layout = "constrained"`**（`astro.config.ts`）是正文图能拿到
  `srcset` 的原因。`image.responsiveStyles` 保持默认的 `false` —— 那样 Astro
  不注入任何 CSS，只加 `srcset`/`sizes`，现有排版一个像素都不动。
- **`Card.astro` 必须自己传 `sizes`。** 开了 `layout` 之后 Astro 会拿
  `width` 猜 `sizes`，猜出来是 `440px`，而那张图桌面上只用 216px。
  差一倍，2× 屏就多下一档。理由写在 `Card.astro` 里那段注释。
- **Cloudflare Image Transformations** 现在用不上了 —— 尺寸是构建时算好的，
  不需要 CDN 现算。

## 附：R2 那条路（2026-08-26 退役）

**桶和 `worker/index.js` 都没动**，`https://clarkebelt.org/img/...` 那批老地址
照常能开 —— 站外可能有人引用过。只是新图不再往那儿传了。

撤掉的理由不是它不能用（能用，验证过一整套：直传、CORS、SigV4、缓存头）。
是**它要求你在写文章的时候做技术决定**：

- 这张该传哪个来源？（选错了构建才炸）
- 文件名带尺寸了吗？（忘了就跳版，而且后台改不了）
- 封面的 440 / 720 两档生成了吗？（缺了读者看到裂图）
- 换内容了，改名字了吗？（没改，读者最多一周看到旧图）

四个问题，每篇文章每张图都要回答一遍，答错了没有一个是当场报错的。
搬进仓库之后这四个问题**全部不存在** —— 不是变简单了，是没有了。

换来的是图片进 git。这笔账在 1.2 MB 的量级上明显划算。

要恢复直传：`git log -- public/admin/config.yml docs/图片工作流.md`，
R2 建桶、rclone 批量上传、后台直传配置、那个「字段级 `media_libraries: false`
会连带干掉 `transformations`」的互斥关系，都在历史里。
`scripts/upload-img.mjs` 和 `scripts/make-thumbs.mjs` 也还留着没删。
