# 后台发布

在浏览器里写文章、点一下发布，一分钟后上线。不用打开编辑器，不用手填 frontmatter。

用的是 [Sveltia CMS](https://github.com/sveltia/sveltia-cms)。

## 它是怎么工作的

```
浏览器 /admin/  ──GitHub API──>  仓库里的 .md 文件
                                      │
                                   commit
                                      │
                                      v
                          Cloudflare Pages 自动构建 ──> 上线
```

**没有数据库，没有后端，没有第三方存内容。** 整个后台就是 `public/admin/` 下的
两个文件：一个 HTML 页面和一份 `config.yml`。它在你的浏览器里直接调 GitHub API，
把表单内容写成 md 文件提交进仓库；剩下的和你手写文章走的是同一条路。

这也是选它的主要原因：**它不依赖 Astro。** 更顺手的 Keystatic 是 Astro 集成，
但它的 peer 范围停在 `astro: 2 || 3 || 4 || 5`，这个项目是 7.1.3，装不上。
绑定框架版本就是这个代价。Sveltia 和构建工具完全解耦，Astro 升到 8 也不会碰到它。

唯一需要自己搭的东西是一个 OAuth 中转：GitHub 的 token 交换必须有个地方藏
client secret，不能放在浏览器里。那就是下面第 2 步的 Worker，一个文件，部署一次就不用管了。
（GitHub 之后会支持客户端 PKCE，届时这个 Worker 可以直接拆掉。）

## 0. 先把分支理顺

**这一步不做，后面全是白搭。**

Cloudflare Pages 构建的是 `main`。而仓库现在的状态是：

```
origin/main    8154c4e  Initial commit          ← 只有一行 README，没别的
origin/master  50c8d37  ...                     ← 真正的历史在这条上
本地 master             + 40 多个未提交的改动
```

两条分支**没有共同祖先**——`main` 是建仓库时 GitHub 自动生成的那个空提交，
真正的站在 `master` 上。也就是说 Cloudflare 一直在构建一个只有 README 的分支。

后台是往 `main` 写的（`config.yml` 里的 `branch: main`）。所以先把真正的历史挪过去：

```bash
cd scifi-blog

git add -A
git commit -m "feat: 连载系列、译文出处、后台发布"

# 把真正的历史推成 main。会覆盖掉 main 上那个初始提交 ——
# 那个提交里只有一行 README.md，master 里也有这个文件，没有东西会丢。
git push --force origin master:main

# 本地也切到 main，以后只用这一条分支
git branch -m master main
git branch --set-upstream-to=origin/main main

# 可选：删掉远端 master，免得以后又推错分支
git push origin --delete master
```

推完去 Cloudflare Pages 面板确认一次 production branch 是 `main`，
并且这次构建成功了。

> 上面这些命令没有人替你跑过。确认过再执行。

## 1. 注册 GitHub OAuth App

去 <https://github.com/settings/applications/new>：

| 字段 | 填什么 |
| --- | --- |
| Application name | 随便，比如 `飞向星空 后台` |
| Homepage URL | 你的站点地址 |
| Authorization callback URL | `https://sveltia-cms-auth.你的子域.workers.dev/callback` |

回调地址要等下一步拿到 Worker 地址才知道，所以可以先随便填一个，
部署完 Worker 再回来改。

拿到 **Client ID** 和 **Client Secret**（secret 只显示一次，当场存好）。

## 2. 部署 OAuth Worker

仓库：<https://github.com/sveltia/sveltia-cms-auth>

按它 README 里的 deploy 按钮部署，或者本地 `wrangler deploy`。
部署完会得到一个地址：`https://sveltia-cms-auth.<你的子域>.workers.dev`。

然后在 Cloudflare 面板里给这个 Worker 加环境变量（Settings → Variables）：

| 变量名 | 值 |
| --- | --- |
| `GITHUB_CLIENT_ID` | 上一步的 Client ID |
| `GITHUB_CLIENT_SECRET` | 上一步的 Client Secret，**存成加密的** |
| `ALLOWED_DOMAINS` | 可选但建议填：你的域名，比如 `你的域名.com`。不填的话别人拿你的 Worker 地址也能走这套登录 |

回到第 1 步把 callback URL 改成 `<Worker 地址>/callback`。

## 3. 填进配置

`public/admin/config.yml` 里有两处占位符要改：

```yaml
backend:
  base_url: https://sveltia-cms-auth.你的子域.workers.dev # ← 改成真的

site_url: https://example.com # ← 改成真的（astro-paper.config.ts 里那个也一起改）
```

提交推送，等 Cloudflare 构建完，打开 `https://你的域名/admin/`，
用 GitHub 登录。能看到文章列表就成了。

本地也能用：`npm run dev` 然后开 <http://localhost:4321/admin/>。
它读写的仍然是 GitHub 上的仓库，不是你本地的文件——这点要记住。

## 4. 日常发一篇

1. 打开 `/admin/`，左边选「文章」，点新建
2. **文件名**：小写英文加短横线，比如 `dyson-sphere-1`。这决定网址。
3. 标题、摘要、正文照着写。正文是富文本编辑器，也能切到 Markdown 源码。
4. 标签选栏目
5. 是连载就展开「连载系列」填系列名和第几部分；是译文就展开「原文出处」
6. 点 Publish

后台会提交到 `main`，Cloudflare 收到推送自动构建，大约一分钟后上线。

`uid` 那一栏是自动生成的，不用管也别改——它是给以后的评论和浏览量当锚点用的。

## 5. 几个会咬人的地方

**文件名发出去之后不能改。** 网址是从文件名推出来的，改了外链和收藏全断。
后台里改「文件名」这一栏也**不会**重命名文件，只会让 frontmatter 里那行
和真实文件名不一致。想改网址就新建一篇、把旧的删掉。

**别填未来的发布时间。** 静态站不会自己到点更新。填了未来时间，
这篇在构建时直接不生成，不报错，就是不存在。要排档期得配 Deploy Hook + 定时任务，
见 [翻译工序.md](翻译工序.md) 里那一节。

**草稿在本地也看不到。** `postFilter` 无条件排除草稿，`npm run dev` 里同样不显示。
勾了草稿就只能在后台的编辑器里看。

**配图只能填完整外链。** 填 `/xxx.jpg` 这种站内绝对路径会让构建失败（`ImageNotFound`）。
默认工作流是图片走 R2 外链，见 [图片工作流.md](图片工作流.md)。

**`config.yml` 写错了后台不会拦你。** 它照样让你保存，等构建时 schema 才报错。
改过 `config.yml` 之后，本地跑一次 `npm run build` 确认。

**frontmatter 里会多一行 `slug:`。** 那是后台用来决定文件名的，zod 会忽略它，
不影响任何东西——只是看着有点多余。

## 6. 升级后台

版本在 `public/admin/index.html` 里写死了，没用 `latest`：
后台是发文章的唯一入口，不该让上游某天推个改动就把它弄坏。

升级是主动动作：

```bash
npm view @sveltia/cms version   # 看最新版
# 改 index.html 里的版本号，本地打开 /admin/ 确认还能用，再提交
```

## 7. 手写那条路还在

后台并没有取代文件。`src/content/posts/` 下的 md 文件仍然是唯一的内容来源，
所以想在编辑器里写照样可以：

```bash
npm run uid   # 生成 8 位的短 uid，手写文章用这个
```

长文用编辑器（或 Obsidian 直接打开 `src/content/posts/`）写会舒服得多，
后台适合改个错字、补个摘要、发个短文。两者写的是同一批文件，不冲突。

## 8. 这套方案的边界

- **后台读写的是 GitHub 上的仓库。** 本地未提交的改动它看不见；
  在后台改完之后本地要 `git pull`，否则下次提交会撞车。
- **不是所见即所得。** 后台的编辑器不渲染 callout（`> [!note] 译注`）、
  也不套站点样式。想确认渲染效果还得看构建结果。
- **Sveltia 还没到 1.0**（当前 0.172.4）。它活跃维护、比 Decap 好用得多，
  但版本号意味着接口还可能变。这也是把版本写死的另一个理由。
- **图片没接 R2。** 媒体库指向仓库里的 `public/images`，只适合偶尔一张小图。
  大图仍然走 R2 外链手动贴。
