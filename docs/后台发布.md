# 后台发布

在浏览器里写文章、点一下发布，一分钟后上线。不用打开编辑器，不用手填 frontmatter。

用的是 [Sveltia CMS](https://github.com/sveltia/sveltia-cms)。

## 它是怎么工作的

```
浏览器 /admin/  ──GitHub API──>  仓库里的 .md 文件
                                      │
                                   commit
                                      │
                                      v
                        Cloudflare Workers 自动构建 ──> 上线
```

**没有数据库，没有后端，没有第三方存内容。** 整个后台就是 `public/admin/` 下的
两个文件：一个 HTML 页面和一份 `config.yml`。它在你的浏览器里直接调 GitHub API，
把表单内容写成 md 文件提交进仓库；剩下的和你手写文章走的是同一条路。

这也是选它的主要原因：**它不依赖 Astro。** 更顺手的 Keystatic 是 Astro 集成，
但它的 peer 范围停在 `astro: 2 || 3 || 4 || 5`，这个项目是 7.1.3，装不上。
绑定框架版本就是这个代价。Sveltia 和构建工具完全解耦，Astro 升到 8 也不会碰到它。

唯一需要自己搭的东西是一个 OAuth 中转：GitHub 的 token 交换必须有个地方藏
client secret，不能放在浏览器里。那就是下面第 2 步的 Worker，一个文件，部署一次就不用管了。
（GitHub 之后会支持客户端 PKCE，届时这个 Worker 可以直接拆掉。）

下面三步只做一次，全在浏览器里，做完就再也不用碰。
唯一要留神的是第 1 步和第 2 步互相要对方的地址，所以先看完再动手。

## 1. 注册 GitHub OAuth App

去 <https://github.com/settings/applications/new>：

| 字段 | 填什么 |
| --- | --- |
| Application name | 随便，比如 `飞向星空 后台` |
| Homepage URL | `https://clarkebelt.org` |
| Authorization callback URL | `https://sveltia-cms-auth.chen202028.workers.dev/callback` |

回调地址是照「你的 workers.dev 子域 `chen202028` + 下一步那个 Worker 的默认名
`sveltia-cms-auth`」推出来的，所以现在就能填。**部署完 Worker 回来对一眼**：
万一账号里已经有同名 Worker，Cloudflare 会给它加个后缀，那就得把这里、
以及 `config.yml` 里的 `base_url` 一起改成真实地址。

拿到 **Client ID** 和 **Client Secret**（secret 只显示一次，当场存好）。

## 2. 部署 OAuth Worker

仓库：<https://github.com/sveltia/sveltia-cms-auth>

按它 README 里的 deploy 按钮部署（会让你授权 Cloudflare 访问 GitHub、
然后 fork 一份到你自己名下），或者 clone 下来本地 `wrangler deploy`。

**注意这是一个独立的 Worker，跟本站没有关系**，别在这个仓库里部署它。
部署完的地址应该是 `https://sveltia-cms-auth.chen202028.workers.dev`。

然后在 Cloudflare 面板里给这个 Worker 加环境变量（Settings → Variables）：

| 变量名 | 值 |
| --- | --- |
| `GITHUB_CLIENT_ID` | 上一步的 Client ID |
| `GITHUB_CLIENT_SECRET` | 上一步的 Client Secret，**存成加密的**（Secret，不是普通 Variable） |
| `ALLOWED_DOMAINS` | `clarkebelt.org`。不填也能跑，但那样别人拿到你的 Worker 地址就能借它走这套登录。想同时从旧的 workers.dev 地址登后台就用逗号隔开两个 |

部署完**核对一次真实地址**是不是
`https://sveltia-cms-auth.chen202028.workers.dev`。不一样的话，第 1 步的
callback URL 和 `config.yml` 里的 `base_url` 都要改成真实的那个。

以后再换域名，`ALLOWED_DOMAINS` 记得跟着改，否则后台登录会被自己挡掉。

注意 callback URL 里是 **OAuth Worker 自己的**地址（`sveltia-cms-auth.chen202028.workers.dev`），
它跟站点域名无关，换域名时不用动。

## 3. 配置这边不用改

`public/admin/config.yml` 已经填好了，包括 `base_url`：

```yaml
backend:
  base_url: https://sveltia-cms-auth.chen202028.workers.dev
site_url: https://clarkebelt.org
```

只有上面那种重名的情况才需要动它。

**再换域名时，`site_url` 和 `astro-paper.config.ts` 里的 `url` 要一起改** ——
后者管 canonical、OG 图、RSS 和 sitemap，漏改的话站能开，但搜索引擎
照 canonical 认为你的内容在别的地址上。

打开 <https://clarkebelt.org/admin/>，用 GitHub 登录。能看到文章列表就成了。
（`config.yml` 改动不需要重新构建站点，刷新页面就生效——但这次它在仓库里，
所以得先推上去。）

## 3.5 另一条路：直接改本地文件（不用 OAuth）

Sveltia 还有个「本地仓库」模式，**不需要 OAuth Worker，也不需要代理服务器**，
直接读写你硬盘上的文件：

```bash
npm run dev
# 浏览器开 http://localhost:4321/admin/index.html
# 点「Work with Local Repository」，选 scifi-blog 这个目录
```

改完的东西直接落在 `src/content/posts/` 下，用 `git diff` 就能看见。
预览照常开 <http://localhost:4321/>。

**两个硬限制：**

- **必须用 Chromium 系浏览器**（Chrome / Edge / Brave / Chromium）。
  它依赖 File System Access API，**Firefox 和 Safari 里没有这个按钮**。
  Brave 还要去 `brave://flags/#file-system-access-api` 手动开。
- **它不做任何 git 操作。** fetch、pull、commit、push 全部要你自己来。
  这一点和线上模式正相反：线上模式点发布就是一个 commit。

改过 `config.yml` 或者刚 `git pull` 过，要手动刷新后台页面。
配置里的 `local_backend` 这个选项 Sveltia 直接忽略，不用加。

## 4. 日常发一篇

1. 打开 `/admin/`，左边选「文章」，点新建
2. **文件名**：小写英文加短横线，比如 `dyson-sphere-1`。这决定网址。
3. 标题、摘要、正文照着写。正文是富文本编辑器，也能切到 Markdown 源码。
4. 标签选栏目
5. 是连载就展开「连载系列」填系列名和第几部分；是译文就展开「原文出处」
6. 点 Publish

后台会提交到 `main`，Cloudflare 收到推送自动构建，大约一分钟后上线。

`uid` 那一栏是自动生成的，不用管也别改——它是给以后的评论和浏览量当锚点用的。

## 5. 几个会咬人的地方

**文件名发出去之后不能改。** 网址是从文件名推出来的，改了外链和收藏全断。
后台里改「文件名」这一栏也**不会**重命名文件，只会让 frontmatter 里那行
和真实文件名不一致。想改网址就新建一篇、把旧的删掉。

**别填未来的发布时间。** 静态站不会自己到点更新。填了未来时间，
这篇在构建时直接不生成，不报错，就是不存在。要排档期得配 Deploy Hook + 定时任务，
见 [翻译工序.md](翻译工序.md) 里那一节。

**草稿在本地也看不到。** `postFilter` 无条件排除草稿，`npm run dev` 里同样不显示。
勾了草稿就只能在后台的编辑器里看。

**配图只能填完整外链。** 填 `/xxx.jpg` 这种站内绝对路径会让构建失败（`ImageNotFound`）。
默认工作流是图片走 R2 外链，见 [图片工作流.md](图片工作流.md)。

**`config.yml` 写错了后台不会拦你。** 它照样让你保存，等构建时 schema 才报错。
改过 `config.yml` 之后，本地跑一次 `npm run build` 确认。

**frontmatter 里会多一行 `slug:`。** 那是后台用来决定文件名的，zod 会忽略它，
不影响任何东西——只是看着有点多余。

## 6. 升级后台

版本在 `public/admin/index.html` 里写死了，没用 `latest`：
后台是发文章的唯一入口，不该让上游某天推个改动就把它弄坏。

升级是主动动作：

```bash
npm view @sveltia/cms version   # 看最新版
# 改 index.html 里的版本号，本地打开 /admin/ 确认还能用，再提交
```

## 7. 手写那条路还在

后台并没有取代文件。`src/content/posts/` 下的 md 文件仍然是唯一的内容来源，
所以想在编辑器里写照样可以：

```bash
npm run uid   # 生成 8 位的短 uid，手写文章用这个
```

长文用编辑器（或 Obsidian 直接打开 `src/content/posts/`）写会舒服得多，
后台适合改个错字、补个摘要、发个短文。两者写的是同一批文件，不冲突。

## 8. 这套方案的边界

- **线上模式读写的是 GitHub 上的仓库**（本地模式见第 3.5 节，那个读硬盘）。
  线上模式看不见本地未提交的改动；在后台改完之后本地要 `git pull`，
  否则下次提交会撞车。
- **不是所见即所得。** 后台的编辑器不渲染 callout（`> [!note] 译注`）、
  也不套站点样式。想确认渲染效果还得看构建结果。
- **Sveltia 还没到 1.0**（当前 0.172.4）。它活跃维护——最近 30 天发了 21 个
  版本，npm 上累计 601 个——但这个节奏本身就说明接口还在动。
  这是把版本写死的主要理由：升级要是主动的动作，不是某天早上突然发生的事。
- **后台脚本从 unpkg 这个 CDN 加载**，1.9 MB（gzip 后约 500 KB）。
  意思是 unpkg 挂了或者被墙，后台就打不开——站本身不受影响，它是纯静态的。
  真在意这一点的话，把那个 js 下载到 `public/admin/` 里改成本地引用即可，
  代价是升级要手动换文件。
- **图片没接 R2。** 媒体库指向仓库里的 `public/images`，只适合偶尔一张小图。
  大图仍然走 R2 外链手动贴。
