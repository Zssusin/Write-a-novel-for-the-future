# 后台发布

在浏览器里写文章、点一下发布，一分钟后上线。不用打开编辑器，不用手填 frontmatter。

用的是 [Sveltia CMS](https://github.com/sveltia/sveltia-cms)。

## 它是怎么工作的

```
浏览器 /admin/  ──GitHub API──>  仓库里的 .md 文件
                                      │
                                   commit
                                      │
                                      v
                        Cloudflare Workers 自动构建 ──> 上线
```

**没有数据库，没有后端，没有第三方存内容。** 整个后台就是 `public/admin/` 下的
两个文件：一个 HTML 页面和一份 `config.yml`。它在你的浏览器里直接调 GitHub API，
把表单内容写成 md 文件提交进仓库；剩下的和你手写文章走的是同一条路。

这也是选它的主要原因：**它不依赖 Astro。** 更顺手的 Keystatic 是 Astro 集成，
但它的 peer 范围停在 `astro: 2 || 3 || 4 || 5`，这个项目是 7.1.3，装不上。
绑定框架版本就是这个代价。Sveltia 和构建工具完全解耦，Astro 升到 8 也不会碰到它。

## 1. 登录：粘一个访问令牌

**不需要 OAuth App，不需要自己部署任何服务器。**

Sveltia 的 GitHub 后端支持四种登录方式，其中最省事的一种是直接给它一个
GitHub 个人访问令牌。上游 README 的判据是：GitHub 后端 + 只有你自己（或技术用户）
用这个后台 → 就用令牌，别搭 OAuth。这个站正好是这种情况。

选它的真正理由不是省事，是**权限范围**：OAuth App 拿到的 token 覆盖你账号下
**所有仓库**，这是 OAuth App 加 `repo` scope 的固有特性，收不窄。
而 fine-grained PAT 可以锁死在这一个仓库、只给 Contents 读写。
同样是一个存在浏览器里的凭证，能碰到的东西少一个数量级。

### 建令牌

登录框里那个链接直接用就行，它指向的是 **fine-grained** 令牌页，而且已经预填了
`Contents: write`。想手动去也一样：

<https://github.com/settings/personal-access-tokens/new?name=Sveltia+CMS&contents=write>

（这个地址是从 Sveltia 0.172.4 的 bundle 里抄出来的，它就是这么拼的。）

链接**没有**替你决定的两项，得自己选：

| 字段 | 填什么 |
| --- | --- |
| Expiration | 自己定。到期要重建一次，这是特性不是麻烦 |
| Repository access | **Only select repositories** → 只勾 `Write-a-novel-for-the-future` |

默认的 Repository access 不是"只有这一个仓库"，**这一项必须手动改**，
否则令牌的范围比需要的大。这是整套设置里唯一真正要留神的地方。

权限那边确认最终是这两项就够：

| 权限 | 级别 |
| --- | --- |
| Contents | **Read and write**（链接已预填） |
| Metadata | Read（勾了 Contents 自动带上，取不掉） |

因为 `config.yml` 里没有设 `publish_mode`，后台是直接提交到 `main`、不走 PR，
所以 Pull requests 权限用不到。真要开编辑工作流再回来加。

### 用它登录

打开 <https://clarkebelt.org/admin/>，点 **Sign In with Token**，粘进去。
能看到文章列表就成了。

令牌存在浏览器的 **localStorage** 里。这一点跟 OAuth 没有区别——OAuth 走完
token 同样落在浏览器里，所以别把令牌法当成"更不安全"。区别只在权限范围和过期。

换浏览器、换设备、清了站点数据，都要重新粘一次。

### 配置这边不用改

`public/admin/config.yml` 已经是对的：`backend` 段**故意没有 `base_url`**，
那一行只有走 OAuth 才需要（见附录）。

**再换域名时，`site_url` 和 `astro-paper.config.ts` 里的 `url` 要一起改** ——
后者管 canonical、OG 图、RSS 和 sitemap，漏改的话站能开，但搜索引擎
照 canonical 认为你的内容在别的地址上。

## 2. 另一条路：直接改本地文件（连令牌都不用）

Sveltia 还有个「本地仓库」模式，**不需要令牌，也不需要联网**，
直接读写你硬盘上的文件：

```bash
npm run dev
# 浏览器开 http://localhost:4321/admin/index.html
# 点「Work with Local Repository」，选 scifi-blog 这个目录
```

改完的东西直接落在 `src/content/posts/` 下，用 `git diff` 就能看见。
预览照常开 <http://localhost:4321/>。

**两个硬限制：**

- **必须用 Chromium 系浏览器**（Chrome / Edge / Brave / Chromium）。
  它依赖 File System Access API，**Firefox 和 Safari 里没有这个按钮**。
  Brave 还要去 `brave://flags/#file-system-access-api` 手动开。
- **它不做任何 git 操作。** fetch、pull、commit、push 全部要你自己来。
  这一点和令牌模式正相反：那边点发布就是一个 commit。

改过 `config.yml` 或者刚 `git pull` 过，要手动刷新后台页面。
配置里的 `local_backend` 这个选项 Sveltia 直接忽略，不用加。

## 3. 日常发一篇

1. 打开 `/admin/`，左边选「文章」，点新建
2. **文件名**：小写英文加短横线，比如 `dyson-sphere-1`。这决定网址。
3. 标题、摘要、正文照着写。正文是富文本编辑器，也能切到 Markdown 源码。
4. 标签选栏目
5. 是连载就展开「连载系列」填系列名和第几部分；是译文就展开「原文出处」
6. 点 Publish

后台会提交到 `main`，Cloudflare 收到推送自动构建，大约一分钟后上线。

`uid` 那一栏是自动生成的，不用管也别改——它是给以后的评论和浏览量当锚点用的。

## 4. 几个会咬人的地方

**文件名发出去之后不能改。** 网址是从文件名推出来的，改了外链和收藏全断。
后台里改「文件名」这一栏也**不会**重命名文件，只会让 frontmatter 里那行
和真实文件名不一致。想改网址就新建一篇、把旧的删掉。

**别填未来的发布时间。** 静态站不会自己到点更新。填了未来时间，
这篇在构建时直接不生成，不报错，就是不存在。要排档期得配 Deploy Hook + 定时任务，
见 [翻译工序.md](翻译工序.md) 里那一节。

**草稿在本地也看不到。** `postFilter` 无条件排除草稿，`npm run dev` 里同样不显示。
勾了草稿就只能在后台的编辑器里看。

**配图只能填完整外链。** 填 `/xxx.jpg` 这种站内绝对路径会让构建失败（`ImageNotFound`）。
默认工作流是图片走 R2 外链，见 [图片工作流.md](图片工作流.md)。

**`config.yml` 写错了后台不会拦你。** 它照样让你保存，等构建时 schema 才报错。
改过 `config.yml` 之后，本地跑一次 `npm run build` 确认。

**frontmatter 里会多一行 `slug:`。** 那是后台用来决定文件名的，zod 会忽略它，
不影响任何东西——只是看着有点多余。

## 5. 升级后台

版本在 `public/admin/index.html` 里写死了，没用 `latest`：
后台是发文章的唯一入口，不该让上游某天推个改动就把它弄坏。

升级是主动动作：

```bash
npm view @sveltia/cms version   # 看最新版
# 改 index.html 里的版本号，本地打开 /admin/ 确认还能用，再提交
```

## 6. 手写那条路还在

后台并没有取代文件。`src/content/posts/` 下的 md 文件仍然是唯一的内容来源，
所以想在编辑器里写照样可以：

```bash
npm run uid   # 生成 8 位的短 uid，手写文章用这个
```

长文用编辑器（或 Obsidian 直接打开 `src/content/posts/`）写会舒服得多，
后台适合改个错字、补个摘要、发个短文。两者写的是同一批文件，不冲突。

## 7. 这套方案的边界

- **令牌模式读写的是 GitHub 上的仓库**（本地模式见第 2 节，那个读硬盘）。
  令牌模式看不见本地未提交的改动；在后台改完之后本地要 `git pull`，
  否则下次提交会撞车。
- **不是所见即所得。** 后台的编辑器不渲染 callout（`> [!note] 译注`）、
  也不套站点样式。想确认渲染效果还得看构建结果。
- **Sveltia 还没到 1.0**（当前 0.172.4）。它活跃维护——最近 30 天发了 21 个
  版本，npm 上累计 601 个——但这个节奏本身就说明接口还在动。
  这是把版本写死的主要理由：升级要是主动的动作，不是某天早上突然发生的事。
- **后台脚本从 unpkg 这个 CDN 加载**，1.9 MB（gzip 后约 500 KB）。
  意思是 unpkg 挂了或者被墙，后台就打不开——站本身不受影响，它是纯静态的。
  真在意这一点的话，把那个 js 下载到 `public/admin/` 里改成本地引用即可，
  代价是升级要手动换文件。
- **图片没接 R2。** 媒体库指向仓库里的 `public/images`，只适合偶尔一张小图。
  大图仍然走 R2 外链手动贴。
- **令牌会过期。** 到期后后台会登不上，表现是 API 报 401。重建一个粘进去即可，
  不用改任何配置。

## 附录：OAuth 那条路（现在不需要）

只有一种情况需要它：**要让不懂技术的人也来写稿。** 让别人自己去 GitHub 建
fine-grained PAT 不现实，那时候「用 GitHub 登录」这个按钮才值得那套基础设施。

现在不要做。记在这里是为了那天不用重新查。

三件事：

1. **注册 OAuth App**（<https://github.com/settings/applications/new>）
   - Homepage URL：`https://clarkebelt.org`
   - Authorization callback URL：`<Worker 地址>/callback`
   - **Enable Device Flow 不要勾。** Sveltia 走标准 authorization code flow，
     用不到它；开着等于多一个可以被诱导授权的入口。
   - Client Secret 只显示一次。它**只该**出现在下一步那个 Worker 的加密变量里 ——
     不进仓库、不截图。
2. **部署 <https://github.com/sveltia/sveltia-cms-auth>**。这是个**独立 Worker**，
   别在本仓库里部署。变量面板属于 Worker，所以得先部署完才有地方填变量：
   Dashboard → 那个 Worker → **Settings → Variables**（新版叫 Variables and Secrets）。

   | 变量名 | 类型 | 值 |
   | --- | --- | --- |
   | `GITHUB_CLIENT_ID` | 普通文本 | 上一步的 Client ID |
   | `GITHUB_CLIENT_SECRET` | **加密**（Encrypt / Secret） | 上一步的 Client Secret |
   | `ALLOWED_DOMAINS` | 普通文本 | `clarkebelt.org` |

   加完要保存并部署才生效。`ALLOWED_DOMAINS` 填的是**主机名**：不带 `https://`、
   不带路径和端口，多个用逗号隔开，支持 `*.example.com` 这种通配符。
   标着 optional，但不填就是任何域名都能拿你的 Worker 换 token。
   **别写 `*.workers.dev`** —— 那等于让任何人的 workers.dev 站点借用它，
   而它手里握着能读写你全部仓库的 secret。
3. **把 Worker 地址填回 `config.yml`** 的 `backend.base_url`（现在故意没有这一行）。

注意 callback URL 里是 **Worker 自己的**地址，跟站点域名无关，换域名时不用动；
但 `ALLOWED_DOMAINS` 要跟着站点域名改，否则你会被自己挡在后台外面。

**这条路的固有代价**：OAuth App 的 token 覆盖你账号下所有仓库，收不窄。
所以真走到这一步时，值得考虑改用 GitHub App 而不是 OAuth App。
（GitHub 之后支持客户端 PKCE 的话，这整个 Worker 可以直接拆掉。）
