# 正文里能写的东西

标准 markdown 之外，这个站还认下面几种写法。全部在 `.md` 里可用，**不需要
改成 `.mdx`** —— 后台（Sveltia CMS）的文章集合写死了 `extension: md`，
换扩展名那些文章就从后台消失了。

---

## 中文里的加粗

按标准 markdown 写就行，**紧贴汉字不用留空格**：

```markdown
有一部名为**《飞向星空》（To the Stars）**的宏大史诗
```

这一条值得单独写一句，是因为**默认的 markdown 并不支持它**。CommonMark 判断
一对 `**` 能不能成对，看的是紧挨着它的那个字算不算标点 —— 而中文的
`《》（）“”` 全是标点，于是上面这行两头都判不成立：开头的 `**` 后面是 `《`，
开不了；结尾的 `**` 前面是 `）`，收不了。结果是整段加粗**静默失效**，
星号原样打在页面上，构建不报错。

所以 `astro.config.ts` 里挂了 `remark-cjk-friendly`（CommonMark 那份 CJK 友好
提案的实装），汉字和标点相邻时按中日韩的规矩判断。它只放宽、不收紧 ——
原来能加粗的写法一个都不受影响。

不装它的话就只能在正文里手动补空格（`名为 **《飞向星空》** 的`），
既要每个作者都记住这条规则，中文里还会多出可见的空格。

## 数学公式

行间公式（独占一段，居中）：

```markdown
$$
\Delta v = v_e \ln R
$$
```

行内公式（夹在句子里）：

```markdown
比冲 $I_{sp}$ 越高，同样的 $\Delta v$ 需要的推进剂越少。
```

语法是 LaTeX，由 KaTeX 渲染。KaTeX 支持的命令列表：
<https://katex.org/docs/supported>

### 几件要知道的事

**样式表只加载到用得上的文章上。** 构建时有个插件（`utils/remark/mathFlag.ts`）
扫一遍文章有没有公式，有才在那一页挂 `<link>`。一篇公式都没有的文章，
HTML 里连 katex 这个词都不会出现。所以别担心「加了这个功能全站变重」。

**字体是按需下载的。** `public/katex/fonts/` 里有 20 个 woff2，但浏览器只会
取实际用到的那两三个。

**升级 katex 之后要重新同步一次：**

```bash
npm run sync:katex
```

忘了跑也没关系 —— `npm run build` 会先检查版本，对不上直接停下来告诉你。
（不检查的话后果很隐蔽：新版 KaTeX 生成的 class 名对不上旧样式表，
公式会渲染成一堆散落的斜体字母，而构建一声不吭。）

**公式不算进字数。** 阅读时长统计只数汉字和拉丁词，公式里的符号跳过。

## 剧透块

```markdown
:::spoiler[第三章的结局]
主角其实早就死了。
:::
```

渲染成一个默认收起的折叠块，点标题展开。

标题有三种写法：

```markdown
:::spoiler[方括号写法]          ← 推荐。标题里可以带 **加粗**、`代码`
:::spoiler{title="属性写法"}    ← 标题是纯文本时用
:::spoiler                      ← 不写，显示默认的「剧透」
```

用的是浏览器原生的 `<details>`，所以键盘操作、读屏播报、以及 Ctrl+F
页内查找时自动展开，全都是白拿的，没有额外的 JS。

⚠️ **必须是三个冒号的块写法。** 写成行内的 `:spoiler[...]` 不会折叠 ——
折叠块是块级元素，塞进句子里是非法 HTML。真写错了不会报错，
只会退化成一个普通的 `<span>`，句子还是完整的。

## 图片和图注

markdown 的第三个参数（本来只做鼠标悬停提示）会变成图下面那行图注：

```markdown
![替代文字](./img/foo.webp "这句会变成图注")
```

**路径是相对的**，图放在 `src/content/posts/img/`。这样 Astro 才认得出它是
本地资源，构建时替你量尺寸、补 `width`/`height`（防跳版）、生成 `srcset`。
写成 `/img/...` 或者外链就都拿不到，`npm run check:posts` 会提醒。

**替代文字（方括号里那句）得自己写** —— 那是给读屏的人的，机器补不了。
空着的话 check:posts 会数出来，但不拦构建。详见 `docs/图片工作流.md`。

（2026-08-26 之前图片在 R2 上，文件名末尾必须带 `-宽x高`，构建时靠读文件名
补尺寸。那条规矩已经废掉了 —— 现在尺寸是真量出来的。）

`/charts/*.svg` 是另一套约定：那些文件会被**内联**进页面，好让图表跟着
明暗主题变色。理由写在 `utils/rehype/figures.ts` 顶部。

### 图号和「见图 3」

**写了图注的图会自动编号**，图注开头出现「图 1」「图 2」……没写图注的图不占号。
编号按图在正文里出现的顺序来，改不了，也不用手写。

侧栏的**文章目录下面会多出一份「图表」清单**，列出这一篇所有带图注的图，
点一条就跳到那张图。少于两张时不显示（和文章目录同一条规矩）。

正文里要指某张图，写 `:fig[3]`：

```markdown
承力结构见 :fig[3]。
```

渲染成一个指向那张图的链接，显示为「图 3」——**「图」字由指令补上**，
所以写「见 :fig[3]」，不是「见图 :fig[3]」。

为什么不直接手写 `[见图 3](#fig-3)`：手写要你自己记住图号，而图号是按出现
顺序编的 —— 中间插一张图，后面所有引用**静默指错**。`:fig[3]` 让工具知道
「3 是个图号」，于是构建时会挨个校验：

```
[figures] 正文里引用了「图 99」，但这篇只有 9 张带图注的图。
```

指不中就构建失败，不会带着一个断掉的「见图 99」发出去。（手写的 `#fig-N`
链接也一样校验。）方括号里不是数字（比如 `:fig[前面那张]`）就当普通文字，
不报错也不生成链接。

### 点开看大图

正文里的图片自动带灯箱，读者点一下就能全屏看原尺寸：

- 桌面：滚轮缩放、按住拖动、双击放大、← → 在同一篇文章的图片之间切换
- 触摸：双指缩放、双击放大、单指拖动
- Esc 或点空白处关闭

被 `[![]()](链接)` 包成链接的图**不参与灯箱** —— 点它应该跳走，
那是写链接时的本意。

鼠标移上去时图片的边框会变成强调色，这就是「这张能点」的提示（抄的
Atomic Rockets：他家用图片边框的颜色表示链接状态）。灯箱是运行时装上的，
所以 JS 没跑起来时边框不会变 —— 不会骗读者去点一张点不开的图。

## 提示框

用 GitHub 风格的 callout 语法（由 rehype-callouts 渲染）：

```markdown
> [!quote] 站主原话
> 这些方法简陋得可怕，但比你自己瞎编数字好太多了。

> [!warning] THERE AIN'T NO STEALTH IN SPACE
> 太空里没有隐形。
```

## 引文框

整段引用别人的东西时用这个，它比 `>` 多了两样：**从哪引的**、**谁写的**。

```markdown
:::source[Atomic Rockets · Basic Design]{href="https://projectrho.com/…" by="Winchell Chung"}
这些方法「horribly simplistic」（简陋得可怕），
但「far better than just making up your figures」（比你自己瞎编数字好太多了）。
:::
```

渲染成一个规则线框：上下两条粗线封口，来源名在顶上、和正文之间隔一条细线，
署名右对齐落在下粗线**外面**——和三线表「资料来源」注是同一个位置。

三样都可以不写：

```markdown
:::source[方括号写法]              ← 推荐。来源名里可以带 **加粗**、`代码`
:::source{from="属性写法"}         ← 来源名是纯文本时用
:::source{href="…"}                ← 给来源名加链接，颜色跟着框走，不变成链接蓝
:::source{by="署名"}               ← 作者、年份，右下角那行
:::source                          ← 都不写，退化成一个纯规则线的框
```

**什么时候用 `> [!quote]`、什么时候用这个**：`[!quote]` 是「原文对照」，
给的是译文旁边那句需要逐字比对的英文，读者已经知道出处是哪篇；
`:::source` 是「引一段别处的东西进来」，读者需要知道它从哪来、谁说的。

⚠️ 和剧透块一样必须是三个冒号的块写法，写成行内的 `:source[...]`
会退化成 `<span>`。

## 加一种新的自定义块

改一个文件：`src/utils/remark/directives.ts`，在 `HANDLERS` 里加一条。

比如想要一个发动机参数卡 `::engine{name="NERVA XE" isp="841"}`：

```ts
const HANDLERS: Record<string, Handler> = {
  spoiler(node, options) { /* 已有 */ },

  engine(node) {
    if (node.type !== "leafDirective") return;
    node.data ??= {};
    node.data.hName = "div";
    node.data.hProperties = {
      class: "engine-card",
      "data-name": node.attributes?.name ?? "",
      "data-isp": node.attributes?.isp ?? "",
    };
  },
};
```

然后去 `src/styles/typography.css` 给 `.engine-card` 加样式。

三种指令语法对应三种节点类型：

| 写法 | 节点类型 | 适合 |
| --- | --- | --- |
| `:::name` | `containerDirective` | 有多段内容的块 |
| `::name` | `leafDirective` | 独占一行、内容全在属性里 |
| `:name[文字]` | `textDirective` | 句子中间的一小段 |

没登记的指令名不会报错，只会退化成一个普通容器（内容不丢）。
这是故意的：文章是在后台编辑的，写错一个指令名就让整站构建失败，
代价比显示成一个 div 大得多。
