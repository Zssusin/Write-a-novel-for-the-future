# 正文里能写的东西

标准 markdown 之外，这个站还认下面几种写法。全部在 `.md` 里可用，**不需要
改成 `.mdx`** —— 后台（Sveltia CMS）的文章集合写死了 `extension: md`，
换扩展名那些文章就从后台消失了。

---

## 数学公式

行间公式（独占一段，居中）：

```markdown
$$
\Delta v = v_e \ln R
$$
```

行内公式（夹在句子里）：

```markdown
比冲 $I_{sp}$ 越高，同样的 $\Delta v$ 需要的推进剂越少。
```

语法是 LaTeX，由 KaTeX 渲染。KaTeX 支持的命令列表：
<https://katex.org/docs/supported>

### 几件要知道的事

**样式表只加载到用得上的文章上。** 构建时有个插件（`utils/remark/mathFlag.ts`）
扫一遍文章有没有公式，有才在那一页挂 `<link>`。一篇公式都没有的文章，
HTML 里连 katex 这个词都不会出现。所以别担心「加了这个功能全站变重」。

**字体是按需下载的。** `public/katex/fonts/` 里有 20 个 woff2，但浏览器只会
取实际用到的那两三个。

**升级 katex 之后要重新同步一次：**

```bash
npm run sync:katex
```

忘了跑也没关系 —— `npm run build` 会先检查版本，对不上直接停下来告诉你。
（不检查的话后果很隐蔽：新版 KaTeX 生成的 class 名对不上旧样式表，
公式会渲染成一堆散落的斜体字母，而构建一声不吭。）

**公式不算进字数。** 阅读时长统计只数汉字和拉丁词，公式里的符号跳过。

## 剧透块

```markdown
:::spoiler[第三章的结局]
主角其实早就死了。
:::
```

渲染成一个默认收起的折叠块，点标题展开。

标题有三种写法：

```markdown
:::spoiler[方括号写法]          ← 推荐。标题里可以带 **加粗**、`代码`
:::spoiler{title="属性写法"}    ← 标题是纯文本时用
:::spoiler                      ← 不写，显示默认的「剧透」
```

用的是浏览器原生的 `<details>`，所以键盘操作、读屏播报、以及 Ctrl+F
页内查找时自动展开，全都是白拿的，没有额外的 JS。

⚠️ **必须是三个冒号的块写法。** 写成行内的 `:spoiler[...]` 不会折叠 ——
折叠块是块级元素，塞进句子里是非法 HTML。真写错了不会报错，
只会退化成一个普通的 `<span>`，句子还是完整的。

## 图片和图注

markdown 的第三个参数（本来只做鼠标悬停提示）会变成图下面那行图注：

```markdown
![替代文字](/img/2026/foo-1200x800.webp "这句会变成图注")
```

**文件名里的 `-宽x高` 不是装饰**，构建时会读它来补 `width`/`height`，
不写的话图片加载时正文会往下跳一次（CLS）。`npm run check:posts` 会把
漏写尺寸的图列出来。详见 `docs/图片工作流.md`。

`/charts/*.svg` 是另一套约定：那些文件会被**内联**进页面，好让图表跟着
明暗主题变色。理由写在 `utils/rehype/figures.ts` 顶部。

### 点开看大图

正文里的图片自动带灯箱，读者点一下就能全屏看原尺寸：

- 桌面：滚轮缩放、按住拖动、双击放大、← → 在同一篇文章的图片之间切换
- 触摸：双指缩放、双击放大、单指拖动
- Esc 或点空白处关闭

被 `[![]()](链接)` 包成链接的图**不参与灯箱** —— 点它应该跳走，
那是写链接时的本意。

## 提示框

用 GitHub 风格的 callout 语法（由 rehype-callouts 渲染）：

```markdown
> [!quote] 站主原话

> [!warning] THERE AIN'T NO STEALTH IN SPACE

```

## 加一种新的自定义块

改一个文件：`src/utils/remark/directives.ts`，在 `HANDLERS` 里加一条。

比如想要一个发动机参数卡 `::engine{name="NERVA XE" isp="841"}`：

```ts
const HANDLERS: Record<string, Handler> = {
  spoiler(node, options) { /* 已有 */ },

  engine(node) {
    if (node.type !== "leafDirective") return;
    node.data ??= {};
    node.data.hName = "div";
    node.data.hProperties = {
      class: "engine-card",
      "data-name": node.attributes?.name ?? "",
      "data-isp": node.attributes?.isp ?? "",
    };
  },
};
```

然后去 `src/styles/typography.css` 给 `.engine-card` 加样式。

三种指令语法对应三种节点类型：

| 写法 | 节点类型 | 适合 |
| --- | --- | --- |
| `:::name` | `containerDirective` | 有多段内容的块 |
| `::name` | `leafDirective` | 独占一行、内容全在属性里 |
| `:name[文字]` | `textDirective` | 句子中间的一小段 |

没登记的指令名不会报错，只会退化成一个普通容器（内容不丢）。
这是故意的：文章是在后台编辑的，写错一个指令名就让整站构建失败，
代价比显示成一个 div 大得多。
