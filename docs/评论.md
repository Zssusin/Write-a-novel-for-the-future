# 评论

评论用 [giscus](https://giscus.app)：读者发的每条评论都存成仓库 GitHub
Discussions 里的一条回复。站本身还是纯静态的，没有数据库、没有后端、
没有要备份的东西 —— 这也是选它而不是 Waline/Twikoo 的理由，那两个都要
自己维护一个存储后端。

代价说在前面：**读者必须有 GitHub 账号才能发言。** 对一个中文科幻站来说
这是个不小的门槛，愿不愿意接受自己判断。不接受的话别在这个文件上加东西，
换一个方案重写 `src/components/Comments.astro` 就行，配置那一层
（`features.comments`）是通用的。

默认是关的。关着的时候页面上没有评论区、也不向 giscus.app 发任何请求。

## 开启：三步

### 1. 仓库开 Discussions

仓库 → Settings → General → Features → 勾上 **Discussions**。

仓库必须是**公开**的。私有仓库上 giscus 装不了 —— 匿名读者读不到私有仓库的
discussion。

### 2. 装 giscus app

去 <https://github.com/apps/giscus>，Install，授权范围选**只给这一个仓库**
（不要选 All repositories）。

### 3. 拿四个 id

打开 <https://giscus.app>，在「仓库」一栏填 `owner/repo`。它会当场校验前两步
做没做，然后在页面下方生成一段 `<script>`。

**只从那段脚本里抄四个值**，别整段复制（本站的脚本是自己注入的，理由写在
`Comments.astro` 顶部）：

| 页面上的属性        | 填到配置里的        | 长什么样             |
| ------------------- | ------------------- | -------------------- |
| `data-repo`         | `repo`              | `Zssusin/xxx`        |
| `data-repo-id`      | `repoId`            | `R_kgDOxxxxxx`       |
| `data-category`     | `category`          | `Announcements`      |
| `data-category-id`  | `categoryId`        | `DIC_kwDOxxxxxx`     |

分类建议选 **Announcements**：这个分类只有仓库维护者能开新帖，读者只能在
giscus 已经建好的帖子下面回复。选 General 的话任何人都能在你的 Discussions
里另开话题，那些帖子和文章对不上，纯粹是噪音。

「Discussion 标题包含页面 xxx」那一组单选**不用管** —— 本站不走那套匹配，
见下面一节。

拿到之后填进 `astro-paper.config.ts` 的 `features.comments`，那里已经留了一段
注释掉的模板。

## 一篇文章对应哪个 discussion：用 uid，不用 URL

giscus 默认按页面 URL 或 pathname 找对应的 discussion。**本站没用那个**，用的是
`mapping: "specific"` + `term = 文章的 uid`。

理由和 `src/content.config.ts` 里 uid 那段注释是同一条：文章 URL 是从**文件路径**
推出来的，改个文件名、挪个目录，URL 就变了。拿 pathname 当匹配键的话，重命名
一次 = 这篇文章底下的评论全部消失（数据还在 GitHub 上，但页面再也找不到那条
discussion 了）。uid 是写下就不改的，本来就是为这种外挂数据准备的键。

副作用：Discussions 列表里的标题会是 `sdzpdael` 这样一串随机码，不好认。
想认得出来的话进 GitHub 手动改标题就行 —— giscus 匹配的是 term 不是标题，
改了不影响。

## 性能

giscus 的 iframe 设了 `loading="lazy"`，滚到评论区附近才真正加载。评论区在
文章最底下，大部分读者读完就走、根本不会触发它 —— 所以开了评论也不影响
文章页的首屏。这一条写在 `Comments.astro` 里，别顺手删掉。

## 主题

站的明暗切换会同步给 giscus（`Comments.astro` 里用 MutationObserver 盯
`<html data-theme>`，变了就 postMessage 给 iframe）。用的是 giscus 自带的
light / dark 两套主题，没做自定义配色。想让它更贴近本站的话，giscus 支持传一个
自托管 CSS 的 URL 当主题 —— 那是另一件事，需要时再说。

## 关掉

把 `features.comments` 改回 `false`。页面上的评论区立刻消失，已经发过的评论
仍然留在 GitHub Discussions 里，不会丢；改回来就又出现了。
