# 站标

一颗带环的行星。「克拉克带」指地球同步轨道那条环带 —— 一条以科幻作家命名的
真实轨道，正好是这个站站的那道缝。环带这个意象同时接着站点背景图（卡西尼拍的
土星，见 `src/styles/glass.css`），所以两处视觉是一套。

## 唯一的源文件是 `public/favicon.svg`

另外两份都是从它派生的：

| 文件 | 用途 | 主题感知 |
| --- | --- | --- |
| `public/favicon.svg` | 现代浏览器的标签页图标 | ✅ 内嵌 `prefers-color-scheme` |
| `public/favicon.ico` | 老浏览器兜底（16/32/48 三档） | ❌ 浅色版 |
| `public/apple-touch-icon.png` | iOS「添加到主屏幕」，180×180 | ❌ 浅色版 |

**改了 SVG 要做两件事**，否则标签页和主屏图标会是两个不同的标、或者干脆不更新：

1. 重新生成后两份（下面有命令）
2. 把 `src/layouts/Layout.astro` 里的 `ICON_VERSION` +1

## 第 2 步为什么不能省

浏览器把 favicon 存在一个**和普通 HTTP 缓存分开**的库里 —— Chrome 的 `Favicons`、
Firefox 的 `favicons.sqlite`。那个库基本不看 `cache-control`，
`Ctrl+Shift+R` 也刷不掉它。

后果是：换了图标之后，**所有访问过这个站的人**都可能长期继续看到旧的。
这不是理论问题 —— 从 Astro 那个 A 换成现在这个站标时就撞上了，服务器发的
是新文件（`curl` 拿到的 `content-length` 对得上），HTML 的 `<link>` 也对，
但浏览器标签页上纹丝不动。

`?v=N` 是唯一可靠的办法：不同 URL 就是不同缓存键。

> 自己想立刻看到新图标：开一个隐私窗口。那里没有旧缓存，
> 能直接区分「服务器发错了」和「本地缓存没刷」。

## 重新生成

```bash
# 1. 从 SVG 栅格化出 ico 需要的三档 + iOS 那张
node -e "
const sharp=require('sharp'), fs=require('fs');
const svg=fs.readFileSync('public/favicon.svg');
(async()=>{
  for (const s of [16,32,48])
    await sharp(svg,{density:s*12}).resize(s,s).png().toFile(\`/tmp/ico-\${s}.png\`);
  // iOS 不支持透明，得自己铺底色；四周留 10px 边，图标不会顶到圆角
  await sharp(svg,{density:2160}).resize(160,160)
    .extend({top:10,bottom:10,left:10,right:10,background:'#e9eef7'})
    .flatten({background:'#e9eef7'}).png().toFile('public/apple-touch-icon.png');
})();
"

# 2. 打包成多尺寸 ico
magick /tmp/ico-16.png /tmp/ico-32.png /tmp/ico-48.png public/favicon.ico

# 3. 确认三档都在里面
magick identify public/favicon.ico
```

## 改设计时要知道的几件事

**XML 注释里不能出现 ASCII 双连字符。** 这一条是踩过的：注释里写了
`--foreground`（CSS 变量名），librsvg 直接拒绝解析整个文件：

```
XML parse error: Comment must not contain '--' (double-hyphen)
```

浏览器可能宽容，但 `sharp` / `magick` 这条栅格化链会当场失败。想在注释里
提 CSS 变量，就只写 `foreground`，别带前缀。

**环是用 mask 挖过的，不压在星球上。** 因为「环从星球前面穿过去」那种画法
需要靠底色描边才看得清，而底色随主题变，靠不住。挖掉之后只剩左右两片，
单色也能读。

**几个数值是为 16px 定的，别随手改小：**

- `stroke-width: 3` —— viewBox 是 32 宽，栅格到 16px 时这条线只有 1.5 物理像素。
  再细会被抗锯齿抹成一片灰，整个标只剩一个圆点。
- mask 圆 `r=9.8` 对星球 `r=7.8`，2px 的缝在 16px 下只剩 1 物理像素。
  再小环和星球就糊成一个椭圆了。
- 没画卫星光点。16px 下任何小于 2px 的细节只会变成一团脏点。

改完务必按三档看一遍（16 / 32 / 256），别只看大图。

## 颜色

取自 `src/styles/theme.css`：

| | 星球 | 环 |
| --- | --- | --- |
| 浅色 | `#0d1729`（foreground） | `#0b6f8a`（accent） |
| 深色 | `#e8f0ff` | `#55ccdd` |

改主题色的话这里要跟着改 —— SVG 里是写死的字面值，不是 CSS 变量
（favicon 在文档之外加载，拿不到页面的 `:root`）。

## 有两份图形，改了要改两处

| 位置 | 形态 | 颜色怎么来的 |
| --- | --- | --- |
| `public/favicon.svg` | 独立文件 | 写死的字面色 + `prefers-color-scheme` |
| `src/components/Header.astro` | 内联 SVG | `currentColor` + `stroke-accent` |

**为什么不共用一份。** 页头那个不能写成 `<img src="/favicon.svg">`：
独立 SVG 文件里的 `prefers-color-scheme` 跟的是**系统**主题，而本站有自己的
明暗切换按钮（往 `<html>` 上写 `data-theme`）。系统浅色 + 站内切到深色时，
`<img>` 版的图标就和页面对不上了。

内联之后 `currentColor` 继承那个 `<a>` 的文字色、`stroke-accent` 走
`var(--accent)`，两者都跟着 `data-theme` 走 —— 四种组合（系统浅/深 ×
站内浅/深）都对。实测过深色下星球变 `#e8f0ff`、环变 `#55ccdd`。

也不能把 `favicon.svg` 的内容直接内联进去：那个文件里有一段 `<style>`，
里面的 `.planet` / `.ring` 内联后会变成**全局**类选择器，泄进整个页面。

**所以改站标是三步**：改 `favicon.svg` → 重新生成 ico / apple-touch-icon →
同步改 `Header.astro` 里那段内联 SVG 的几何参数。再把 `ICON_VERSION` +1。

## 页头尺寸是算出来的

`size-8` / `max-sm:size-7` 不是随手挑的。Michroma 的 `capHeight` 是
1536/2048 = 0.75em，桌面端 `text-xl`（20px）下约 15px。
星球直径 = 7.8×2/32 × 图标边长，所以 `size-8`（32px）给出 15.6px，和字高齐平。
小一档（`size-7`）只有 13.6px，看着像掉了一号 —— 试过，确实偏小。

手机端量过有余量：`size-7` + `gap-2` + `text-lg` 的字标，在 390px 宽下
离汉堡按钮还有富余。
