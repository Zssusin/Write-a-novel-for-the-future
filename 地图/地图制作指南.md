- SVG 是给印刷和改字用的：**除了底图晕渲是嵌入的位图，海岸线、经纬网、铁路、符号、文字全是真矢量**，浏览器直接打开，文字可选中可改。
- PNG 是 SVG 的 3 倍渲染（约 5500 px 宽），直接放进书稿或发给编辑。
- Gemini 做的深色 HUD 版（`旧版_HUD/`）已于 2026-09-14 删除。

## 1. 风格：白底、简约、仿官方行星地形图

参照的是 USGS / NASA 出的行星地形图（例如 USGS I-2782《火星地形图》）的做法，不是照抄它们的标志：

| 元素 | 做法 |
|---|---|
| 纸 | 纯白，图廓外留白放图名、图例、说明 |
| 底图 | MOLA 高程**晕渲** × **低饱和分层设色**。晕渲是 **多向加权晕渲**（Mark 1992，USGS 的 MDOW 做法：225°/270°/315°/360° 四个光源，每个像元按 sin²(坡向−光源方位) 加权，再绕平地值做对比度拉伸），乘上 **天空可见度因子**（Zakšek 2011：16 个方向找地平线仰角，谷底、坑底四周被挡就变暗）。单光源会把与光线平行的地貌压平——奥林匹斯断崖只剩半圈、水手峡谷的北壁支谷丢光——多向 + 天空可见度两样都补回来。分层设色之上再乘一层 **MGS TES 反照率**（±9% 明度，暗区另去色 35%）：大瑟提斯、子午线湾、厄立特里亚海这些望远镜时代的暗区在图上有了轮廓，塔西斯、阿拉伯的浮尘区更亮——真实火星地形图的「火星感」主要来自这一层。刻意压低饱和度，让地形和注记当主角 |
| 水面 | 浅蓝，按水深由浅到深，海底地形淡淡透出来；海岸线是 0.6 宽的中蓝细线 |
| 经纬网 | 0.35 宽黑线、不透明度 28%。**经纬网是背景，不是主角** |
| 图廓 | 单线图框 + 框外刻度：大刻度 6、小刻度 3。**每度一个小刻度最能提升可信度**——说明这图是量出来的 |
| 注记 | 没有底框，靠 2.3 宽的白色描边（`paint-order="stroke"`）压在地形上 |
| 地名分级 | 水体：蓝色、字距展开，下附斜体英文；陆地区域：灰色、字距展开，下附斜体英文大写；城镇：黑色，主要城市加粗并附英文 |
| 沿线排字 | 长条水体和河流的名字**沿地物走向弯着排**（战区图的水手峡谷海沿峡谷轴线、路线图的回声河沿河、极区图的北方海沿纬线弧）。逐字定位、按切线旋转，不用 SVG `textPath`（librsvg 不支持） |
| 等高线 | 棕色 0.3 宽，间隔 1,000 m；每 5,000 m 一根**计曲线** 0.6 宽，沿线注高程数字，数字自动找直的线段、避开地名 |
| 等深线 | 与海岸线同色、0.4 宽、半透明，间隔 1,000 m |
| 呼吸线 | 紫色虚线 + 以上区域的紫色细斜线。图上高过这条线的高程数字也用紫色 |
| 淹没带 | 蓝色细斜线：海面再涨 200 m 会淹掉的沿岸土地 |
| 预测岸线 | 蓝色虚线，沿线注「−6,000 m 岸线」：海拉斯海涨到该水位时的岸线（正典：22 世纪会成为自给自足的海洋） |
| 径流水道 | 细蓝线，粗细按集水面积分三级：把 MOLA 地形的洼地填平后按最陡方向汇流算出，只画流向海拉斯的 |
| 集水区界 | 黑色长短虚线：所有往海拉斯流的地面的外缘。真实地形上占全火星 11%，正典说「15% 以上」 |
| 时区界 | 棕色点划线：正典的六个时区之一的界线（60°E），绕开海拉斯海 |
| 土地利用 | 绿色只给土地利用。`22_土地利用.py` 按地形算出 **农田**（总量 12,000 km²，按正典农区分配配额，取适宜度最高的格子）、**草场 / 已绿化带**（沿海 22 km、沿常年河 10 km 内的低地，河道只算切入真谷地的）、**水产**（红湖）、**城区**（推定人口 ÷ 密度，穹顶城按正典尺寸）。区域图（塔西斯、北方海、海拉斯）只画草场带——农田总共只有天津那么大，在区域图上是几个像素，画了反而生硬；**战区图整层不画**（用户 2026-09-14：平地上按汇流算出的河道太直，绿带显得生硬）。城区只在城区图上画得出来 |
| 唯一的强调色 | **氧化红只给闸坝**——全图只有这几个点是这个颜色，因为它们是军事目标。例外：尺度对比图不画闸坝，红色专给地球对照物 |

**图上不冒用 NASA / USGS 的抬头或标志**，只在图下出处里如实写明底图数据来自 MGS MOLA（NASA GSFC · USGS 拼接）。这些是 2100 年虚构世界的地图，风格仿官方，身份不冒充。

## 2. 投影

| 图 | 投影 | 为什么 |
|---|---|---|
| 卷首全图 | **摩尔威德（Mollweide）等积投影，中央经线 280°E** | 最有「星球感」；等积意味着各海面积比例是对的。中央经线放在 280°E，让塔西斯和水手峡谷落在画面中心，海拉斯和伊利瑟姆分列两侧，接缝落在 100°E（没有重要地点） |
| 战区图 | **等距圆柱**，238–334°E × 5°N–20°S | 正交方格，可数格子量相对位置。战区只跨 25 个纬度，变形可以忽略 |
| 参考图 | 等距圆柱，0–360°E | 查坐标用。高纬度东西向严重拉伸，别拿它量极区距离 |
| 塔西斯区域图 | **墨卡托**，192–272°E × 22°S–32°N，赤道比例与战区图相同 | USGS 火星分幅图在 ±30° 内也用墨卡托。保角，火山画出来是圆的。纬度越高比例越大，所以图上给了赤道和 30°N 两把比例尺 |
| 北方海极区图 | **北极心兰伯特等积方位**，画到 5°N；300°E 朝下 | 海绕极一圈，只有极心投影能一眼看全。等积，各海湾面积可比。0° 经线不朝下而是 300°E 朝下，让克律塞湾和战区在下方 |
| 海拉斯区域图 | **兰伯特等积方位**，中心 39°S 70°E，矩形图框 | 盆地是圆的，方位投影以它为心变形最小；经纬线在图上是弧线，四条边分别注经度（上下）和纬度（左右） |
| 尺度对比图 | 兰伯特等积方位（叠中国、叠北冰洋）、正射（地球仪） | 火星和地球各自以中心展开、用同一个「屏幕单位/千米」，面积和距离可以直接比 |

**建议书里放两张：卷首全图 + 战区图。** 正典自己就是这么做的（p19/p20 全球 + p22 战区），几乎所有带地图的小说也都是「世界图 + 详图」。情节转到中国腹地或北方海沿岸时，再用塔西斯区域图、北方海极区图做章节图；剖面图和尺度对比图适合放附录。

### 火星特有的一条：经度双标

正典地图用**西经**，SpaceEngine / Mars Trek / USGS / QGIS 用**东经**。新图**图框上沿标东经、下沿标西经**。这本身就是世界观细节：火星殖民地沿用旧惯例，地球的科研机构早就转东经了。

## 3. 让 2100 年的地图立刻可信：标日期

**2100 年的火星地图必须标日期，因为海岸线在动。** 每张地形图右上角都有一行红字：

> **海岸线测绘于 2100 年 3 月　北方海仍在上涨，本图岸线逐年失效**

正典写得很清楚：北方海仍在上涨，维京公园正在修堤，几十年内会被淹到近一英里深；北方海沿岸「没有真正的永久聚落」，房子每隔几年就要往坡上搬一次。按新水位，**维京公园只高出海面 78 m、离岸 47 km；卡尔·萨根纪念站只高出 18 m、离岸 3 km**。

同一逻辑还用了两次（北方海极区图另有一张表，列出每个沿岸聚落离海面多高，海面涨过这个数就进城）：

- **赤道铁路**在 2100 年 7 月下旬才于 Escalante 合龙。标「2100 年 3 月」的图上，**Escalante 以东那段画成虚线未通车**。书里前后放两张图，缺口补上了——无字的时间流逝。
- **中美边界**：正典从没划过线。图上不画国界，只用符号形状区分归属，并在图例里注明。**边界的缺席正是战争的前提。**

**另一条让地图可信的线：呼吸线。** 正典说海拔 5 英里（8,047 m）以上气压太低，连基因改造的人都无法呼吸（ITW p.34）。塔西斯区域图把这条等高线画成紫色虚线，线内加斜线；剖面图上也画了这条线。它在地图上是一条**垂直的战术边界**：新上海、宙斯度假区火山口分部都在线以上。

## 5. 字体

| 用途 | 字体 | 理由 |
|---|---|---|
| 中文图名、地名 | **FandolHei**（本机已装） | 黑体，小字号清晰，与官方地形图的无衬线风格一致 |
| 拉丁地名、数字、刻度 | **Liberation Sans** | 与 Helvetica 等宽，官方行星图常用这一类无衬线体 |
| 正典描图版 | LXGW WenKai 霞鹜文楷 + CMU Serif | 纸质海图的书卷气，那张图保留原样 |

SVG 里写的是字体名，换一台没装 FandolHei 的电脑会回退到其他黑体；**印刷用 PNG 最稳**。

注意：中文注记整串都由 FandolHei 画，包括里面的数字和「·」（FandolHei 的「·」是全角宽）。`制图公共.text_width()` 按这个规则量字宽，注记避让才准。

## 7. 管线与重跑

```
DEM + IAU 地名库 + 正典
   │
   ├─ scripts/10_MOLA海平面标定.py     单阈值扫描与 DEM 自检（诊断用）

   │                                     ↓ 产出/三海掩膜.npz
   ├─ scripts/12_导出海岸线.py         → 海岸线_2100.gpkg / .geojson、海岸线_多级海侵.geojson
```

## 9. 踩过的坑

**真实地形管线**

1. **降采样必须取最小值，不能取平均**：平均会抹平窄海峡，海被切成孤立的湖。
2. **连通填充的种子不能取「北半球最低点」**：那是 Lyot 陨坑（−7,032 m），孤立深坑。
3. **单一种子会漏水**：Ius 峡谷在 −3,300 m 下是 8 块互不连通的小盆，坎多尔湖在 −3,800 m 下和 Melas 也不连通。改成「该段峡谷范围内所有低于水面的洼地」。
4. **正典 p22 是示意画法**：图框准，图里的峡谷偏南约 3°、厄俄斯湖偏 5–7°。只从它读地点之间的关系，不读坐标。
5. **skimage 的形态学重建用 float32 会算错**，找火山口时必须转 float64。
6. **地图接缝**：等距圆柱和摩尔威德都要在接缝处断开折线和海岸线，否则跨接缝的线会被拉成横贯全图的直线。已经在 `制图公共.py` 里处理。
7. 注记避让：符号占位框必须小于注记与符号的间距，否则每个注记连自己的符号都绕不开（剖面图第一版就是这样丢了一半地名）。
8. **最小值降采样只给连通判断用**。晕渲、剖面、面积用它会整体偏低、偏暗，所以另做了平均值缓存。
9. 投影后的栅格（极区图、地球仪）直接在屏幕网格上矢量化海岸线，不要先在经纬度上矢量化再投影：那样 ±180° 接缝会在极区图上拉出一条径向直线。
10. 投影后的栅格底图要比图框多画一圈，否则圆形图框在上下左右四个点会露白边。
11. 墨卡托区域图的晕渲在等距圆柱上算好（坡度按真实像元尺寸），再按行重采样成墨卡托，比在墨卡托网格上算坡度简单且准。
12. **渲染器会吞掉行首空白，连全角空格也吞**。说明文字的续行缩进只能挪 x 坐标，见 `制图公共.note_lines()`。
13. 尺度对比要用各自的半径展开：火星 3,396 km、地球 6,371 km，同一个「屏幕单位/千米」。用同一个投影对象画两个星球，面积会差三倍半。
14. **方位投影里经过对跖点的经纬线会跳成一条贯穿图幅的直线**：中央经线的对跖经线正好压在中央经线上，图廓刻度和度数会印两遍。`graticule_frame` 按段长切掉跳段。
15. 曲线经纬网只让经度在上下边注字、纬度在左右边注字，否则在同一条边上两种标注互相压。
16. 汇流计算：填洼后的湖面是平的，D8 找不到更低的邻元；平地要一圈圈向已有流向的同高邻元靠（Garbrecht–Martz 的思路）。汇流按拓扑序（入度为 0 先算）用 `np.add.at` 分批做，几百万格几秒钟。
17. numpy 2 不再支持二维向量的 `np.cross`，多边形面积用鞋带公式自己写。
18. 计曲线数字要在城镇注记**全部放完之后**再注，并先给每个城镇符号扩一圈占位框（约 ±11 px），否则数字会贴着城市符号（塔西斯图海源城旁曾出现「5000」）。扩框若放在城镇注记之前，会把城镇自己的注记顶飞。
19. 极点、图心这类参考点用细十字，不要用实心圆点——会和锈色中国的城镇符号混淆。
20. 两个相对定位的地点（如迈尔堡「紧邻红湖」）在区域图比例下 20 km 只有 6 px，符号会叠成「8」；推定距离取 35 km 以上，或改用不同符号。
21. **多向晕渲直接平均会发灰**：四个方向的亮暗互相抵消，标准差只有单光源的 3/4。平地值 cos(天顶角) 不动，把偏差乘 1.7 拉回来即可；别用直方图均衡，会把平原里的噪声也拉出来。
22. 天空可见度别用 `np.roll` 逐方向整幅复制：塔西斯窗口 1,770 万像元 × 16 方向 × 8 步会复制上百次 70 MB 的数组。改用切片：只在「自己和目标像元都在图内」的矩形上算 `dz/dist`，并原地 `np.maximum(out=)`。整幅 15 s。
23. 等距圆柱窗口的东西向像元宽 `dx_m` 是按行广播的列向量；天空可见度里算距离要把它切成和 `dz` 同样的子矩形，否则形状对不上。
24. **librsvg 2.62 不支持 `textPath`**，沿线排字只能逐字 `<text transform="rotate()">`。逐字反而更好：每个字有自己的包围盒可以登记避让，字距也可控。
25. 沿线排字的方向规则：折线整体从右往左就反转，保证字头朝上、从左往右读；接近竖直时（如南北向的河）按「从下往上读」处理——这是地图的惯例，也和 `rotate` 在 ±90° 内保持字形直立一致。法线取切线右侧，反转折线后左右也跟着换，`offset` 的正负要按反转后的方向想。
26. **TES 反照率原图有轨道条纹和极区十字噪声**：南北向的细条纹是逐轨拼接的痕迹，8 px/度上高斯 σ=1.5 就能压掉而不糊掉暗区边界；78° 以上是十字网格状的噪声，线性淡到中性值（86° 以上全中性）。8 px/度放大到 64 px/度的区域图要用三次样条（`order=3`），双线性会看出格子。
28. **区域图幅的 `Equirect.unwrap` 以前按 lon0 取模**：图框西边线外一点点的顶点会被甩到 +360°，跨西边线的多边形拉出横贯全图的横带（土地利用第一版放大图里两条绿带就是它）。现在区域图幅取离中央经线最近的表示，全球图幅保留旧规则（东边线的点不能甩回西边）。
29. **D8 汇流线不是河**：3,000 km² 的汇流门槛会把每条冲沟都算上，塔西斯熔岩斜坡上的汇流线又长又直，草带跟着它爬满平原，用户一眼看出「直线绿化」。门槛提到 30,000 km²，还要求格子比 28 km 邻域平均低 60 m 以上（真切进谷地的），草场从 468 万 km² 降到 77 万。
30. 适宜度因子别用会饱和到 1 的分段线性：一整片都是 1.0 时 argsort 按下标取格，农田会挤在农区框的北边一行。改 logistic，再乘一个离城镇距离因子（农场围着市场和车站长）。
31. `mask_rings` 平滑后的环首尾差一点点，不闭合；导出 GeoJSON 或算鞋带面积前先把首点补到末尾，否则面积多出一整个三角形。
27. 反照率只调明度和饱和度，不改色相：暗区只是「更灰更暗」，不是另一种颜色，否则和水面的蓝、呼吸线的紫抢戏。分层设色本身已经让高地偏暖、低地偏冷，反照率乘上去就够了。

**正典描图版**

1. 水体灰度范围比看起来宽得多：43–150。
2. 标签白底会产生灰色光晕，落在水体灰度带里：把近白区域膨胀 13 px 后减掉。
3. **连通域筛选必须在闭运算之前**，否则标签残留的细环会被膨胀成实心方块。
4. 方形核留下直角锯齿，最后加一道高斯模糊（σ≈3.2）再二值化。
